# TIN creation

For each tile, `qm_tiler` samples the raster on a regular grid (`--samples-per-tile` samples per side). It then
builds a **Triangulated Irregular Network** (TIN) that approximates those samples with far fewer triangles. The
method is selected with `--tc-strategy`:

| `--tc-strategy` | Method | Controls the result through | Page |
|-----------------|--------|-----------------------------|------|
| `greedy` (default) | Greedy insertion (Garland & Heckbert) | Maximum height error | [Greedy insertion](greedy.md) |
| `lt` | Edge collapse (Lindstrom-Turk) | Number of edges | [Edge collapse](edge-collapse.md) |
| `ps-hierarchy` | Hierarchy point set simplification | Cluster size / surface variation | [Point set](point-set.md#hierarchy-ps-hierarchy) |
| `ps-wlop` | WLOP point set simplification | Percentage of points kept | [Point set](point-set.md#wlop-ps-wlop) |
| `ps-grid` | Grid point set simplification | Cell size | [Point set](point-set.md#grid-ps-grid) |
| `ps-random` | Random point set simplification | Percentage of points removed | [Point set](point-set.md#random-ps-random) |
| `delaunay` | No simplification | — | [below](#delaunay-no-simplification) |

The options of each method start with `tc-` followed by the identifier of the method, e.g. `--tc-greedy-error-tol`
or `--tc-ps-grid-cell-size`. Only the options of the selected method are used.

## Which method should I use?

**Start with `greedy`.** It is the default because, in our tests during the EMODnet Bathymetry project, it gave the
most intuitive control over the quality of the result: you directly set the maximum error, in meters, that you accept
at each zoom. It is also reasonably fast.

- Use `lt` when you want to control the **size of the tiles** (number of edges) rather than the error.
- The `ps-*` methods are mostly of research interest. Since they ignore the connectivity of the samples, they have
  to simplify the borders and the sharp edges of the tile separately, and need more parameters to be tuned.
- Use `delaunay` to keep every sample, e.g. to compare with a simplified result, or to emulate Cesium's old
  heightmap terrain.

To try methods and parameters on a single area before building a whole pyramid, use
[`dem2tin`](../dem2tin.md), which runs only the TIN creation step and writes the mesh to an OFF file. You can also
build one zoom with `-s <z> -e <z> --debug-dir <dir>`, and look at the meshes of the tiles in a mesh viewer.

## Borders between tiles

All the methods except `delaunay` take the borders of the tiles already built as constraints: the vertices on a
shared border are fixed, and the method simplifies the rest of the tile around them. See
[Tile processing](../tile-processing.md) for the details.

## Delaunay (no simplification)

`--tc-strategy delaunay` triangulates all the samples of the tile in the XY plane, with no simplification. It has no
parameters of its own. The complexity of the result depends only on `--samples-per-tile`.

Combined with `--samples-per-tile 64`, it emulates the triangulation that Cesium builds for tiles in the old
[heightmap-1.0](https://github.com/CesiumGS/cesium/wiki/heightmap-1.0-terrain-format) format (as generated by
[cesium-terrain-builder](https://github.com/geo-data/cesium-terrain-builder)), but encoded as quantized-mesh:

```bash
qm_tiler -i dem.tif -o tiles --tc-strategy delaunay --samples-per-tile 64
```
